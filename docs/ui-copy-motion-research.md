# 文言と動きの見直し

確認日: 2026-10-28。今回の「AIっぽい」は生成元の判定ではなく、意味の薄い宣伝句や定型的な見せ方を減らす編集基準として扱う。

## 調査と適用

- [GOV.UK: Writing for user interfaces](https://www.gov.uk/service-manual/design/writing-for-user-interfaces): 画面を詳しく読まない人にも行動が分かるように書く。操作名と次にすることを具体的にする。
- [NN/g: User-centric vs. Maker-centric Language](https://www.nngroup.com/articles/user-centric-language/): 抽象的な宣伝文句や作り手の専門用語より、使う人が理解できる説明を優先する。
- [NN/g: The 3 C’s of Informational Microcopy](https://www.nngroup.com/articles/3-cs-microcopy/): 短さだけでなく、必要な意味を明確に伝える。操作に必要な理由は残す。
- [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md): 文言を飾りに使わず、具体的な用途と操作の説明にする。定型のスローガンや意味のないラベルを避ける。
- [Emil Kowalski: Great Animations](https://emilkowal.ski/ui/great-animations)と導入済みanimate/apple-design: 状態変化の理解に動きを使う。押した直後の反応、中断、移動の連続性を重視する。長い説明用の演出を理由に結果へのアクセスを待たせない。

## 編集する箇所

| 現在の表現                                   | 変更                                                                              |
| -------------------------------------------- | --------------------------------------------------------------------------------- |
| 「大切なことを、相手だけに。」               | 暗号化する機能を直接書く                                                          |
| 「GitHubの公開鍵で、そっと封をする。」       | 宛先の指定方法を短く書く                                                          |
| Dear you / From me                           | 削除。装飾のための英語を置かない                                                  |
| 「ひらくのは、あなただけ。」                 | 削除。送信相手と操作者を混同させない                                              |
| 「相手だけが開ける、ひとつのメッセージに。」 | 「暗号化しました。」                                                              |
| 「あなた宛てのメッセージが、届きました。」   | 「復号しました。」。アプリが通信したように見せない                                |
| OpenPGP / filename、GPGコマンド              | 結果画面から削除                                                                  |
| 暗号化後の案内なし                           | コピー／保存してメール・SNSで渡すことと、実際の宛先の秘密鍵で開けることを短く示す |

暗号化は内容の秘匿を担い、通信経路やアカウントの安全性すべてを保証するものではない。「どんな送信手段でも完全に安全」とは書かず、暗号文を渡せることを説明する。手動公開鍵にGitHubアカウント名を割り当てない。

## 動きと配置

一度の操作に、文字の変形、封入、宛先への受け渡しという流れをつける。封筒・軌跡・波紋の範囲で演出を強め、入力欄や実際の暗号文を読めなくしない。装飾に利用者の本文を複製しない。動きを減らす設定では静的な状態説明を残す。

見た目のためだけの余白でページを少しスクロールさせない。ヘッダーと操作領域の高さを割り当て、コピー・保存・実行を常に見える位置に置く。長い暗号文や展開した補助情報には内部のスクロール領域を使う。
