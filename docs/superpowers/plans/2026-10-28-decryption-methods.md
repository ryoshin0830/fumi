# 復号方法の選択と秘密鍵の案内 — タスクリスト

作成日: 2026-10-28。状態: 実装・ローカル検証・独立レビュー済み。配送結果はPR #2を参照。

**Goal:** 復号する人が最初に「ブラウザーで復号」「コマンドで復号」を選び、その方法に必要な情報だけを使って開けるようにする。

**Architecture:** 既存のHTML/CSS/JavaScriptとローカルWorkerを維持する。復号方法の状態を追加し、暗号文の入力と形式検出は共通化する。ブラウザー側の自動復号と、秘密鍵を読み込まないコマンド案内を分ける。

**Tech Stack:** 既存のNext.js Route Handler、生成HTML、素のJavaScript、OpenPGP.js、age/WASM。追加のUI依存・ネイティブ補助アプリは不要。

## 調査して分かったこと

- [x] `gh auth login`のSSH鍵作成処理を確認。新規作成を選んだ場合、`GenerateSSHKey("id_ed25519", ...)`を呼び、ホームの`.ssh`内に保存する。秘密鍵は通常`~/.ssh/id_ed25519`、公開鍵は同名の`.pub`。
- [x] `gh`は既存の`~/.ssh/*.pub`も選択して登録できる。GitHubへ登録されたSSH公開鍵が、必ず`gh`で生成されたものとは限らない。
- [x] GitHub上の公開鍵には利用者のPCの秘密鍵パスが含まれない。複数PC・複数鍵・別名の鍵もあるため、公開鍵から場所は確定できない。
- [x] ブラウザーはパスを知っていても秘密鍵を自動で読めない。利用者が選択したファイルを読み込む。ファイル選択後も取得できるのはファイル名であり、コマンド用の実際のフルパスとは扱わない。
- [x] ageはSSH Ed25519/RSA秘密鍵ファイルを利用できるが、通常のSSH対応では`ssh-agent`を利用しない。GitのSSH認証が成功することと、ageで復号できる秘密鍵ファイルがあることは別。
- [x] Fumiの現在の暗号化は、利用可能なGPG鍵があればGPGを優先する。GitHub宛という理由でageコマンドを選ばず、受け取った暗号文から判別する。

参照: [gh auth login](https://cli.github.com/manual/gh_auth_login)、[ログイン処理](https://github.com/cli/cli/blob/trunk/pkg/cmd/auth/shared/login_flow.go)、[鍵の生成・保存処理](https://github.com/cli/cli/blob/trunk/pkg/ssh/ssh_keys.go)、[GitHubのSSH鍵作成案内](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/generating-a-new-ssh-key-and-adding-it-to-the-ssh-agent)、[ブラウザーのファイル読み込み](https://developer.mozilla.org/en-US/docs/Web/API/FileReader)、[ageのSSH鍵対応](https://github.com/FiloSottile/age#ssh-keys)。

## 画面の方針

復号タブの初回表示では、同じ大きさの「ブラウザーで復号」「コマンドで復号」を並べ、未選択から始める。どちらかを押すと、その場で選択した方法の内容が開く。確認・次へボタンは追加しない。選択後も同じ場所で方法を切り替えられる。

| 方法       | 表示するもの                                                            | 表示しないもの                                     |
| ---------- | ----------------------------------------------------------------------- | -------------------------------------------------- |
| ブラウザー | 暗号文、秘密鍵ファイルの選択、補助の貼り付け、必要時だけパスワード      | ターミナル用のコマンド                             |
| コマンド   | 暗号文／暗号ファイル、判別した形式のコマンド、SSH秘密鍵のパス、補助Tips | 秘密鍵の内容・秘密鍵ファイルの読み込み・パスワード |

暗号化後の結果には、宛先とメール・SNSでの渡し方、コピー・保存を残す。コマンドTipsは復号側へ移す。復号済みの結果にコマンドを表示しない。

コマンドを選んだ人には、コマンドそのものを主な内容として見せる。鍵の探し方・ツールの準備などの補足を閉じたTipsへまとめる。選択した目的そのものを、さらにTipsの中へ隠さない。

SSH秘密鍵の場所は、`~/.ssh/id_ed25519`を候補として案内できる。検出・確認済みの場所とは表示せず、別のパスを使えるようにする。ブラウザー側では「秘密鍵の場所」Tipsから`.ssh`フォルダーを開く方法を案内し、貼り付けよりファイル選択を使いやすくする。

## 実装タスク

### 1. 復号方法の選択を作る

対象: `src/template.html`、`src/styles.css`、`src/app.js`。

- [x] 方法の状態を`null | 'web' | 'command'`で持つ。初回は`null`、同じ画面を使う間は選択を保持し、「すべて消去」で`null`へ戻す。
- [x] 2択はラベル付きのネイティブradioとし、キーボードと読み上げで選択状態が分かるようにする。プロフィール情報は引き続き非操作の表示とする。
- [x] 方法の選択前は秘密鍵・パスワード・コマンドを隠す。選択すると共通の暗号文入力と該当する方法の内容だけを表示する。
- [x] 既存の操作タブ、編集、暗号文・秘密鍵の下書きを維持する。方法の切り替えで入力を不用意に消さない。

完了条件: 復号タブを開いた人が最初に2択を見て、1回の選択で必要な入力へ進める。追加の決定操作はない。

### 2. ブラウザーで開く流れを整える

対象: `src/app.js`、`src/template.html`、`scripts/browser/disclosure-scenarios.mjs`。

- [x] 秘密鍵ファイルの選択を主な入力にし、貼り付けは補助として利用できるようにする。公開鍵の`.pub`ではなく、対応する秘密鍵が必要であることを入力箇所で分かるようにする。
- [x] `scheduleDecrypt()`と`performOperation()`の両方に方法の条件を加える。`web`を選んだ場合だけ、暗号文と秘密鍵がそろってから既存の600ms待機と自動復号を行う。
- [x] `PASSPHRASE_REQUIRED`の場合だけパスワード欄を出す。鍵違い・壊れた暗号文・誤ったパスワードを区別する既存動作を維持する。
- [x] パスワードと未完了の確認は、方法を切り替える際に解除する。実行中のWorker・タイマー・ファイル読み込み・照合を中止し、遅れて返る結果を表示しない。

完了条件: コマンド側に切り替えても裏で復号やパスワード判定が動かない。ブラウザーへ戻ったときは、下書きから安全に確認を再開できる。

### 3. コマンドで開く流れを作る

対象: `src/ui/result.js`、新規`src/ui/decryption.js`、`src/app.js`、`src/files.js`、`tests/result-view.test.mjs`、新規`tests/decryption-ui.test.mjs`。

- [x] 暗号化結果から`terminal-tips`とコマンド生成処理を外し、復号のコマンド領域へ移す。新モジュールはコマンド生成と表示を担当し、暗号処理やサーバー通信を持たない。
- [x] 既存の`detectFormat(value)`を再利用し、暗号文のヘッダーから`pgp | ssh | null`を判定する。拡張子だけで判定せず、ヘッダー判定だけで暗号文の正当性を検証したとも表示しない。
- [x] GPGにはGPGの、SSH/ageにはageのコマンドだけを出す。GPG側には登録済み秘密鍵を使う案内、age側には秘密鍵パスの入力を出す。
- [x] ファイル選択時は実際のファイル名を使用する。貼り付け時は暗号文を`.asc`／`.age`として保存できる操作を用意し、その保存名をコマンドと一致させる。
- [x] 秘密鍵パスは候補を編集できるようにする。例のパスと検出済みパスを混同せず、ファイル選択で分かった名前をフルパスとして利用しない。
- [x] コマンドのコピーと暗号文ファイルの保存を使いやすく配置する。コピー失敗時にも全文を選択できるようにし、アプリが端末でコマンドを実行したとは表示しない。
- [x] ファイル名・パスの空白、引用符、`$()`、先頭ハイフンをシェルの引数として安全に扱う。コマンド例の対象シェルを明示し、WindowsのパスをPOSIXとして誤って引用しない。

完了条件: コマンド側では秘密鍵の内容を入力せず、受け取った暗号文に合ったコマンドを保存ファイルと合わせて利用できる。

### 4. 鍵の場所と準備のTipsを必要な場所に置く

対象: `src/template.html`、`src/ui/decryption.js`、`docs/design-system.md`、`README.md`。

- [x] 「秘密鍵の場所」には`gh`で新規作成した場合の候補、別名の鍵もあること、`.pub`との違いを短くまとめる。ブラウザー側ではファイル選択、コマンド側ではパス指定に合わせて案内する。
- [x] macOSのファイル選択では`⌘⇧G`から`~/.ssh`を開く操作を案内する。OSに応じたフォルダーの案内とコマンドの表記を混同しない。
- [x] ツール未導入の案内はコマンド側の補足へ置く。復号のために`gh auth login`や新しい鍵の作成を案内しない。既存暗号文を、新しく生成した別の鍵で開けるとは説明しない。
- [x] `ssh-agent`や1Password内だけにある鍵を、自動的に読み取れるような表示をしない。鍵ファイルを使える場合の手順に絞る。

完了条件: 通常の入力は短く保ち、鍵が見つからない人がその場で手掛かりを得られる。
