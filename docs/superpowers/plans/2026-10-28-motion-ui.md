# Fumi Motion UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an Apple-inspired Fumi interface with an encryption transformation, GitHub recipient preview, an unmerged PR, and a verified running local application.

**Architecture:** Keep the generated HTML/vanilla JavaScript UI and crypto worker. Add a bounded public-profile and avatar proxy, a small recipient-preview controller, and a decorative motion controller independent of crypto results.

**Tech Stack:** Next.js 16.4.3 Route Handlers, JavaScript, CSS transitions/animations, Web Animations API or requestAnimationFrame, existing node:test and ego-browser.

## Global Constraints

- Japanese interface, system fonts, no external font or animation runtime.
- Preserve encryption/decryption, manual keys, drafts, cancellation, limits, legacy signatures, complete Copy/Save, and standalone HTML.
- Public profile data never proves usable keys or real-world identity. Content, private keys and passwords stay local.
- Fixed upstream hosts, validated route parameters, no credentials forwarded, bounded response bytes and deadlines.
- Respect reduced motion; keep first-screen access to the tool; never delay a ready result for an animation.
- Work in the existing isolated `tree-pushing-ferry` worktree. The user requested inline execution, PR creation and local startup.

## Task 1: Public GitHub profile and avatar transport

**Files:** Create `src/profiles.js`, `server/github-profile.mjs`, `app/api/github-profile/[username]/route.js`, `app/api/github-avatar/[id]/route.js`, `tests/profiles.test.mjs`, `tests/github-profile-server.test.mjs`.

**Interfaces:** `normalizeProfile(data, username)` returns `{ id, login, name, bio }` with bounded strings and a matching validated login. `loadGitHubProfile(input, { signal, fetcher, backend })` resolves that shape using the existing username parser. `githubProfileResponse(request, { username, fetcher })` and `githubAvatarResponse(request, { id, fetcher })` return bounded no-store Responses.

- [ ] Write transport tests before implementation. Cover exact upstream URL, no forwarded private headers, username/query/method rejection, malformed/mismatched profile, byte limits, 404/rate limit/network failures, abort, timeout, raster-only avatar responses and dynamic route params.

```js
const response = await githubProfileResponse(
  new Request('http://localhost/api/github-profile/octocat'),
  {
    username: 'octocat',
    fetcher: async (url, options) => {
      assert.equal(url, 'https://api.github.com/users/octocat');
      assert.equal(options.credentials, 'omit');
      assert.equal(options.redirect, 'error');
      return Response.json({ id: 1, login: 'octocat', name: 'The Octocat', bio: null });
    },
  },
);
assert.deepEqual(await response.json(), { id: 1, login: 'octocat', name: 'The Octocat', bio: '' });
```

- [ ] Run `node --test tests/profiles.test.mjs tests/github-profile-server.test.mjs`; confirm missing behavior fails, implement the interfaces, rerun to pass.
- [ ] Use fixed profile and avatar origins, 8-second request deadlines, 64 KiB JSON and 256 KiB raster-image limits. Return sanitized public fields only.
