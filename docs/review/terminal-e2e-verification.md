# 端末への貼り付けと秘密鍵入力の確認

## 原因と修正

旧コマンドはEnterを待つ際に1行だけを読み、その後はクリップボードを使っていた。利用者が複数行の鍵を端末へ貼り付けると、最初の行だけが待機で消費され、残りがzshのコマンドとして解釈された。暗号文の入力待ちで秘密鍵を渡すと、GPGも想定外の入力で失敗した。

旧mainのビルドを保持したコンテナに、使い捨ての鍵で同じ操作を行い、`gpg: decrypt_message failed: Unexpected error` と後続の `zsh: command not found` を再現した。利用者の鍵データはテストに使っていない。

- 端末へ貼り付けたブロックは終端まで読み、シェルで評価しない。
- 鍵と暗号文のヘッダーを入力元ごとに確認し、取り違えた場合は入力し直せる。
- 表示を隠してから入力待ちを案内し、終了・失敗・中断時には端末設定を戻す。
- GPGへ実際の端末を `GPG_TTY` で伝え、保護された鍵も対話式に解除する。
- Webでは秘密鍵のtextareaと貼り付け・ファイル操作を直接表示し、パスワードが必要になっても鍵欄を折りたたまない。

## コンテナE2E

実行: `DOCKER_CONTEXT=desktop-linux npm run test:container`。通常のDockerコンテキストでは `npm run test:container`。

本番ビルド・Chromium・日本語フォント・Xvfb・実X11クリップボード・zsh・GnuPG・ageを同じコンテナで起動する。ブラウザーで暗号化・ファイル保存し、画面のCopyで取得したコマンドを変更せずに対話式の疑似端末へ送る。クリップボードはモックしない。鍵は毎回コンテナ内で生成する。

端末は通常のechoと有効な履歴記録から始める。コマンドの通常のエコーを読み終えてから実行時の案内を待ち、入力中のecho無効・終了後の復帰・本文の出力／履歴への非混入・一時鍵の削除・復号結果のバイト一致を確認する。保護鍵は事前解除せず、GPGのpinentry／ageのパスワード入力へキー操作で入力する。

- GPG: 保護あり／なし × 登録済み・鍵ファイル・クリップボード × 暗号ファイル・クリップボード = 12ケース。
- SSH/age: 保護あり／なし × 鍵ファイル・クリップボード × 暗号ファイル・クリップボード = 8ケース。
- 両方を複数行として直接貼り付ける4ケース。
- 暗号文の入力待ちへ秘密鍵を貼り付けた後、正しい暗号文で復帰する1ケース。
- 入力待ちでCtrl+Cを押し、端末表示と一時領域の後始末を確認する1ケース。
- Webの直接貼り付けでGPG・SSHの保護あり／なしを復号する4ケース。
- 1440×900、1366×768、375×667、390×844で、鍵欄とパスワード欄の表示、不要なスクロールと操作ボタンの位置を確認する。

合計26端末ケースとWeb・レイアウト確認。結果は `test-results/container/report.json` と画面画像へ出力する。GitHub Actionsの `container-e2e` ジョブでも実行する。

## その他の確認と限界

本番ビルド、整形、203ユニットテスト、既存CLI互換性12ケース＋UIで可能な入力元15ケース、ブラウザーの既存9グループ・復号方法・段階表示・アニメーション・8サイズ144状態のレイアウトを確認した。バイナリ暗号文のクリップボード方式はUIで選べないため、CLIの入力元テストでも除外する。

独立レビューで見つかった「案内の表示からechoを消すまでの競合」を修正し、通常のechoから即座に貼り付ける再現も成功した。Windows実機とmacOSの実pbpasteはLinuxコンテナで確認した扱いにしない。PowerShellの複数行処理・保護された入力・一時領域削除は構造テストで確認する。
